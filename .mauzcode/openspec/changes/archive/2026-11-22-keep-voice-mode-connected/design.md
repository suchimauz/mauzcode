# Design: A voice session belongs to its chat, not its mounted composer

## Context

- In `src/$ws_voice_session.ts`, `SESSION_MS = 5 * 60_000` starts when the relay is ready. Both the timer and monotonic deadline checks can drive `beginFinish(true)`: stop accepting audio, drain pending phrases, report `timeout`. Valid audio, including generated silence during mute, renews a **separate** 30-second idle guard, not this deadline. `VOICE_SESSION_MS` in `frontend/src/lib/voiceCapture.ts` supplies the UI countdown; hiding it would not fix the disconnect.
- `LiveComposer` keys `SessionComposer` by `agentId`. Panel state, the capture hub, phrase ledger and unsent `File` objects are local to that subtree. `useVoiceCapture` releases on agent change/unmount; `pagehide` is a separate, intentional release. The relay currently arbitrates an `(owner, chat)` lease, not cross-chat dedicated ownership.
- Explicit Send currently calls `finish()`; both core and the provider treat that operation as terminal. See `proposal.md` for why the new lifetime must not depend on navigation, time or a message boundary.

## Goals / Non-Goals

**Goals:** Keep one authorized dedicated session bound to its original chat and route. Never capture in a chat that is merely being viewed, and never route a phrase, file or send to the wrong draft. Make actual termination and deliberate mute distinguishable.

**Non-goals:** Persist live resources across page reloads, change inline dictation into a persistent mode, reconnect around provider limits, change route selection, or record audio/transcripts in a new store. No background-service guarantee when the browser, network or provider actually stops working.

## Decisions

1. **An in-memory coordinator above the keyed chat subtree.** The shell owns one dedicated capture controller per page and identifies its run by owning chat, generation and session ID. Keep the owner's draft binding, phrase ledger, attachments and pending submission key/target with it, using the current per-chat draft path rather than a second transcript. The composer subscribes only to its own binding; leave a terminal notice with that chat. Do not keep every chat's UI mounted or pass new `agentId` props into an old run: both make late callbacks easy to misroute. Scope retained unsent files to the current page; no media or files in durable storage.
2. **Gate audio at the navigation boundary, not in a passive unmount effect.** On in-app departure (including back/forward), latch mute and disable the owner's tracks before switching the visible/subscribed draft. Apply the existing worklet epoch gate: drain only proven pre-mute samples; ambiguous/post-cut samples are zero, never queued for later. If permission, worklet or `ready` is pending, bind it to the original owner; newly obtained tracks start disabled when that owner has left. An old gate acknowledgement cannot re-enable them. The latch survives return; only an explicit foreground unmute for the same live generation releases it. Keep sending valid sequenced digital silence while muted; this needs neither live mic input nor a weaker idle guard. Do not rely on a visual mute icon or simply rerender a panel in B.
3. **Negotiate dedicated lifetime and arbitrate at the relay.** Add an optional start mode (`panel` or `inline`; omission is legacy inline, unknown values are protocol errors) and advertise the accepted mode/boundary support in `ready`. For dedicated runs remove **all** wall-clock finish paths, including on frame receipt/access recheck. Keep start, idle, access and finish deadlines, frame/queue/backpressure bounds, route isolation and the existing same-chat lease. Add an authenticated-owner dedicated lease alongside it, not an instance-wide microphone lock. Claim both after edit authorization and before admitting B's audio. Use monotonic start order and identity-checked release so an older async open/cancel cannot win back or remove a newer claim. A refused start cannot evict; a provider failure after takeover releases the winner without resurrecting A. Navigation and a different chat's inline start never claim this lease. Reject a frontend-only lock: different tabs do not share one JS heap.
4. **Separate a message boundary from terminal `finish`.** Add a negotiated, correlated `settle`/`settled` control pair for the dedicated relay. Start the client finalization deadline on explicit Send, before muting; do not reset it at settlement. On expiry invalidate the attempt before unlocking Send, retain the muted draft and attachments, and ignore late acknowledgements for that attempt. On explicit Send, mute and await the audio-thread gate/cut acknowledgement so pre-mute tail frames precede the request on the socket. Serialize the boundary with appends; flush the speech tail, snapshot the pending orders for this draft and wait boundedly for their final/failed results. For provider-detected turns, require positive evidence that the tail is uncommitted before requesting a commit. An upstream boundary may still be in flight: await its notification and final, or fail on deadline if coverage remains unknown. Continue accepting sequenced silence; no later microphone input until an explicit unmute. A successful boundary does not call provider `finish`, close the socket or allocate a different session. Keep `finish`/`cancel` terminal. Merely muting or navigating does **not** initiate a boundary or a send. Do not guess that a pause means the last phrase is final.
5. **Scope acknowledgement, errors and cleanup.** A send lock and a per-draft boundary ID ensure repeated Enter cannot duplicate recognition or ordinary delivery. Bind the pending operation to the originating chat, draft revision, attachments and existing idempotency key/endpoint. On successful recognition, send/queue once; clear only on ordinary acknowledgement, advance the draft epoch and remain muted. A failed recognition never submits partial text; a lost ordinary acknowledgement preserves the request for explicit retry. Terminal close, page teardown, revocation or supersession invalidates that generation and releases resources once. If it failed away from the owner view, show a sanitized notice (and existing error ID) there on return, not in B. A recoverable phrase error is not itself a disconnect. Never re-enable a microphone from a callback after release.
6. **Replace deadline feedback rather than inventing a new limit.** In dedicated mode show elapsed connection time from `ready`, including mute, in the existing time slot on desktop and touch. Keep actionable muted/listening states and keyboard behavior; remove expiry warnings and ticking live announcements. Preserve explicit Exit as the kill switch. No new global controls are needed to visit another chat.

## Risks / Trade-offs

- **Long connections use resources and may be metered** → keep existing destination disclosure, liveness/backpressure guards and one dedicated run per owner. Avoid retaining settled transcript copies and correlations indefinitely in transport/provider state; keep only live orders and bounded duplicate-detection metadata, separate from the user's editable draft.
- **Browser suspension, upstream session expiry or a broken route** → treat a real disconnect as terminal, including while parked. Show the reason and retain the text; do not extend provider limits or attempt a silent reconnect.
- **Out-of-order permissions, finals, owner changes or sends** → test with deferred promises, two editable chats, concurrent tabs and different owners. Verify bytes and owning drafts, not just icons or WebSocket counts.

## Migration Plan

Ship relay negotiation and bounded settling before enabling the dedicated client path. Older clients omit mode and retain the old finite protocol. A new client must not send `settle` or advertise persistent operation to an old relay that did not negotiate it; use the legacy finite lifecycle for that connection. No DB migration or credential change. Roll back the client first, then the relay; already closed connections are not restored automatically.
