# Design

## Context
See proposal.md for motivation and specs/agent-presets/spec.md for the behavior contract. Prompt content is assembled from the base, capability files, generated sections and additions under immutable preset snapshots. Existing discovery and access predicates already provide the mechanisms needed here. Historical Creator paragraph-equivalence tests describe the original prompt split, not a permanent ban on reviewed optimization.

## Goals / Non-Goals
**Goals:** Reduce repetitive always-present text while keeping actionable safety rules, truthful capability hints and a short discoverable route to detailed rules. Make measurements reproducible and review losses explicitly.

**Non-Goals:** No new instruction-pack loader, grants migration, saved-preset or snapshot rewrite, authorization changes, user-addition rewriting or full Canvas/Input/catalog redesign. No automatic archive, publish or commit.

## Decisions
1. **Use effective access for independent hints.** Review base, `$prompt_*.md`, fullSystemPrompt and tools/input/canvas/plugins generators. Split independently useful capabilities or filter their examples through the existing `allows` predicate. Cover codeGraph (`code.index` is not available to default Standard), sharedAgents and agentMessaging, including custom denies and inherited intersections. Preserve existing exclusion identifiers semantically: a split block must not resurrect guidance excluded by its original identifier. Broadening grants to fit prose is rejected.
2. **Keep host facts separate from project policy.** Put the raw Bun.file/Bun.write server-cwd warning beside permitted eval/workspace guidance, not behind administrative DB/remote access. State that code.* indexes the registered runtime, not arbitrary workspaces. Minimal uses its existing file/shell tools without API or unavailable grep/find directions. Avoid describing every target project as Bun/procs/Postgres.
3. **Use existing documentation discovery instead of permanent reference dumps.** Remove manual namespace lists and expanded ctx/agent structures from evalLegacy; retain opts-only calls, schema discovery and bounded-result recovery in accessible eval/discovery guidance. Shorten codeGraph to purpose and limitations; merge search and read-before-edit/readId duplication without repeating native schemas. Move detailed file grammar, authoring/validation/typecheck/reload procedures and queue schema to project/topical documentation. Retain the runtime DB warning against bare Bun.sql. Runtime/plugin authors outside this repository must have a permitted runtime/plugin documentation route; relative project docs alone are insufficient.
4. **Consolidate project documentation narrowly.** Merge repeated UI/SSR/runtime policy blocks in AGENTS.md and retain concise mandatory rules and a topic map. Align docs/agent-presets.md and applicable architecture/authoring docs. Check touched hot-reload, test-database and platform-startup claims against current code. Track unrelated or unverified infrastructure questions separately rather than rewriting policy from current-machine assumptions.
5. **Preserve meaning rather than old paragraphs.** Keep creator-prompt.before.md immutable. Replace paragraph-equivalence enforcement with current invariant tests and a reviewed record identifying removed duplicates, shortened passages and relocation destinations. Keep actionable secret handling, exact confirmation authority, input waiting, peer trust, transcript/event integrity and actual-effect verification. Do not treat an emitted UI event as executed. Preserve exclusions, additions and their order. The delta intentionally changes the historical scenario's expected check while retaining its scenario identity.
6. **Measure controlled inputs separately.** Capture before state before runtime/documentation edits under a fixed registry, plugin fixture, workspace and empty per-agent additions; reuse that setup after edits. Report assembled prompt characters, generated-section characters and transmitted native-schema size separately; label any token estimates honestly. Target 25–35% Standard/Creator text reduction, but accept a reported shortfall rather than lost guarantees or expanded scope. Explain any Minimal increase. A live mounted-plugin count is not a reproducible fixture.

## Risks / Trade-offs
- [Shorter prompts lose important constraints] → Invariant tests and a reviewed optimization record cover explicit safety rules and relocated destinations, not just size.
- [Partial grants leave stale hints] → Test direct generators and assembled prompts under custom denies and parent/child intersections, not built-ins alone.
- [Split blocks bypass exclusions] → Test stored exclusion identifiers against all replacement guidance without modifying stored snapshots.
- [Documentation becomes unreachable outside MauzCode] → Verify the allowed runtime/plugin discovery route in an external-workspace fixture.
- [Moving content does not meet the size target] → Report controlled before/after figures and residual opportunities; preserve correctness.
- [Parallel work makes validation stale] → Runtime owner coordinates one settled batch and one full-project typecheck owner; rerun affected checks after further edits and retain complete diagnostics.

## Migration Plan
No data migration is required. Work ownership: oc captures baseline and owns prompt/invariant tests; od owns project/documentation consolidation; the parent owns runtime prompt composition and integration. Coordinate fixture freeze before changes. After the batch, hot-reload affected modules rather than restart; validate changed runtime-function metadata strictly with typecheck disabled, then run one full-project typecheck, targeted tests and fast suite. Run integration tests if integration logic changed. Preserve complete diagnostics and distinguish pre-existing failures. Validate the change strictly after every artifact edit and check tasks only on completed evidence. Rollback is a coordinated revert of the changed prompt, test and documentation files, with no preset/snapshot mutation. Leave this change unarchived for review.
