## 1. Registry и настоящая граница инструментов

- `ctx.tools.register(definition, {when?})` принимает `ToolDefinition`, возвращает disposer; регистрация scoped, поддерживает shadowing по agent scope и ограничения allow/deny. `run_code` — **зарезервированный transport**, его нельзя зарегистрировать/затенить как обычный tool. `tools.restrict` не разрешает ограничивать transport вместо конечных capabilities. [registry](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/index.ts#L120-L285).
- `when` вычисляется для шага: false исключает инструмент **и из declarations, и из dispatch**, ошибка condition ломает preparation, а не молча отключает функцию. Step-owned набор сохраняет identity и не допускает подмену регистрации. [contracts](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/contracts.ts#L100-L149).
- Handler возвращает canonical lossless JSON, отдельно объявлены `output.schema`, renderer model-facing `ContentBlock[]`, UI `presentationMeta`. Это **не значит, что native модель всегда видит весь JSON**: часто видит сокращённый текст; PTC получает structured value. Есть `projectContent`/`finalizeContent`, post-execute policy, обязательное соблюдение cancellation signal и quiescence. In-process code нельзя «жёстко убить» одним AbortSignal. Concurrency opt-in: отсутствие/ошибка/non-true `isConcurrencySafe` означает exclusive execution. [контракт](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/contracts.ts#L20-L99).
- `deferLoading` поддерживается schema и DeepSeek wire `defer_loading`; это не доказательство встроенного `tool_search`. Поиск по production sources не обнаружил общего model-visible `tool_search`/`search_tools`; discovery здесь преимущественно preset composition, skill catalog, MCP enumeration, plugin/inspect tools. [schema](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tools/src/schema.ts#L490-L505), [wire](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/llm/llm-deepseek/src/serialize.ts#L150-L168).

## 3. Files, edit, search

| Точное имя | Аргументы и результат / поведение |
|---|---|
| `read` | `file_path`, optional `offset` (1-based), `limit`. UTF-8 text; canonical path + numbered lines и metadata, model-facing line-numbered content с limits. |
| `read_image` | `file_path`; PNG/JPEG/WebP/GIF, автоматическое уменьшение больших изображений, canonical path + image attachment; выдаётся сама картинка, не только имя. |
| `write` | `file_path`, `content`; create или полная замена UTF-8. Результат содержит path, operation, before/after; текст/diff projection. |
| `edit` | `file_path`, `old_string`, `new_string`, `replace_all?`; literal replacement, без replace_all совпадение должно быть ровно одно. Нет readId/hashline аргумента. |
| `apply_patch` | `input` с patch language; optional sandbox escalation. **Не default**: `applyPatch` default false и false в standard. Отдельные preflight/plan/execute modules; не просто alias edit. |
| `glob` | `pattern`, optional `path`; ищет файлы, не директории, **включая hidden и ignored**, в порядке modification time; bounded paths, workspace-relative rendering. Over-cap результат может spill в файл; standard отключает sampleOverCapGlobResults. |
| `grep` | `pattern` ripgrep regex, optional `path`, `include` (один glob, не список и без negation). Canonical matches `{path,lineNumber,line}`; bounded rendering/spill. Поиск **не записывает file observation**. |
| `working_directory` | optional `cd`; без него читает cwd. `{cwd}`. Смена cwd не меняет cwd уже запущенных процессов/существующих shells. |
| `str_replace_editor` | Optional alternative, не standard. `command`: `view/create/str_replace/insert`, `path`, operation-specific `file_text/old_str/new_str/insert_line/view_range`. Не следует ошибочно называть его стандартным `edit`. |

## 4. Execution, jobs и PTC

- **`bash` / `pwsh`**: required `description`, `command`; optional `timeoutMs`, `workdir`, условно `run_in_background`, `sandbox_permissions`, `justification`. Обе background/promotion настройки по умолчанию true, при наличии jobs backend. Обычный output — структурированный process result с rendering stdout/stderr/exit/sandbox; background — `{kind:'background',jobId,cwd}`; timeout promotion — `{kind:'promoted',jobId,cwd,output,…}`. При promotion timeout не убивает процесс; при выключенном promotion timeout применяется как kill. Explicit background не имеет timeout. Persistent implementations существуют **под теми же именами bash/pwsh** и не являются дополнительными стандартными tools. [bash flags и handler](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/shell/tool-bash/src/index.ts#L414-L550), [persistent bash](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/shell/tool-bash-persistent/src/index.ts#L410-L465), [pwsh](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/shell/tool-pwsh/src/index.ts#L429-L470).
- **`job_output`** `{job_id,wait?,timeout_ms?}` читает delta stream с cursor или final result; timeout ожидания оставляет работу живой, возвращает состояние. **`job_list`** `{}` — jobs текущего агента, включая завершённые. **`job_kill`** `{job_id,reason?}` — запрос cancellation; output отличает `cancellation-requested` от `already-finished`. **Запрос kill не доказательство остановки.** [jobs](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/jobs/tool-jobs/src/index.ts#L434-L614).
- **`run_code`** — PTC transport; `code`, `description` required и runtime-specific control/escalation fields. В Node PTC language TypeScript, sandbox-aware subprocess runtime; не Bun eval. Program вызывает bindings зарегистрированных tools; nested calls сохраняют guard/approval/policy/logging. Есть limits на subcalls/concurrency, abort/drain, retained state/runtime reset contracts; нельзя считать arbitrary host JS автоматически безопасным. [transport](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tool-executor-ptc/src/ptc.ts#L220-L320), [dynamic schema](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tool-executor-ptc/src/ptc.ts#L745-L770), [private binding factory](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/core/tool-executor-ptc/src/run-code.ts#L15-L49), [Node runtime](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/ptc-runtime/ptc-runtime-node/src/index.ts#L20-L135).
- **`workflow`** standard tool: `script` — plain JavaScript body (не TypeScript), top-level await, завершение `return <JSON>`, `meta` identity/name/description/phases, optional `args`, `run_in_background`. Output foreground `{kind,runId,agentsStarted,result}` либо background `{kind,jobId,runId}`. Это orchestration engine, не CLI command. [schema/handler](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/workflow/tool-workflow/src/index.ts#L329-L445).

Resume не единый tool: cwd/plan восстанавливаются через session state, дочерние conversations продолжаются `send_message`; streaming job_output возобновляет cursor. Сохранность **живого OS процесса после полного restart host** этим исследованием не доказана; не заявлять durable process resume.

## 8. Permission/sandbox и важные отличия для MauzCode

1. Shipped permission presets: `read-only + ask`, `workspace-write + ask`, `danger-full-access + never`. Default env fallthrough workspace-write. Конкретный execution provider обеспечивает confinement, не prompt: Linux Landlock, macOS Seatbelt, Windows ACL backend/probes; уровень поддержки платформозависим. Нельзя объявлять одинаковую network isolation всех backend без отдельного platform audit. [base policy](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/bundle/base/cordis.patch.yml#L240-L276), [sandbox probes](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/sandbox/sandbox-local/src/index.ts#L565-L619).
2. Escalation поля появляются только когда исполнитель реально поддерживает соответствующий sandbox. `justification` относится к **точному вызову**, approval не означает смену session mode. FS mutation и PTC идут через sandbox policy; plugin_manager отдельно предупреждает о host-wide code. Хороший образец capability-aware schemas + enforcement в execute, а не только в выдаче tools.
3. Plan mode — **collaboration state**, не security mode. Вход CLI `/plan`, model exit с typed review и durable state; sandbox/approval независимо. Это существенный риск для сравнения с системами, обещающими read-only plan mode. [явный комментарий контракта](https://github.com/deepseek-ai/deepseek-harness/blob/39163dd30f703a79079e2d2446545cff3c453738/packages/plan/plan-mode/src/index.ts#L1-L12).
4. Для MauzCode особенно полезны: раздельные canonical value/model render/UI meta; step-time admission с невозможностью подмены; cancellation drained до settlement; concurrency opt-in; async subagent activation и «inactive != success»; exact goal revision; PTC сохраняет вложенный tool audit и approvals; MCP generation preflight; inspect-list/query как discovery без arbitrary write authority.
5. Отличия от видимых инструментов MauzCode в текущей сессии: read/edit здесь не readId/hashline protocol, observation policy default disabled; bash timeout обычно promotes в job, а не сразу kill; goals используют rounds/revision, не token budget; workflow JS и run_code TS — разные интерфейсы; present не немедленный canvas; plugin_manager profile-wide, не локальное изменение проекта.

## Ограничения выводов

Полный deployment-dependent список динамических MCP/user tools нельзя вывести из репозитория без настроенного Host. Не выполнялись real model calls, sandbox probes, network providers, CLI launch или тесты; это source-verified contracts, не end-to-end верификация установки. Experimental ряд подтверждён registration/source locations, но не все параметры каждого experimental handler исследованы с той же глубиной, что core tools. Проверенные defaults привязаны к Web standard/base, а не ко всем profiles. Никаких утверждений о persistent OS-process resume, абсолютной patch atomicity, универсальном сетевом sandbox или полной LSP IDE functionality не делается.
