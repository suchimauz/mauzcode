# Design

## Context

`codexListModels` already calls the subscription catalogue. `models.catalog.listModels` sanitizes `ModelInfo` before writing `llm_connections.models_cache`; `frontendBridge.modelCatalogue` projects only a subset and can discover on a cold cache. `models.inference.stream` already reads the exact route's cached descriptor for reasoning, and `models.call` forwards `providerOptions` through streaming. Today `codexStream` rejects all provider options and forces medium verbosity. See the six spec deltas for the observable contract.

## Goals / Non-Goals

Keep account discovery authoritative for what can be selected; keep SDK callers independent of the chat UI and the adapter independent of sessions. Do not add a generic settings schema, a new model endpoint, subscription checks based on model names, global defaults, context controls or an Ultra execution policy.

## Decisions

1. **Expose capabilities, not wire parameters.** Extend `ModelInfo` with optional `responseControls`, with independent `speed.supported` and `verbosity.{supported,default?}` members using closed string unions. Advertise speed only when at least one accelerated tier is known; include Standard in that list. Normalize and deduplicate names on discovery and validate them on cache writes. Keep generic provider metadata and arbitrary remote strings out of the picker. Use the cache-only catalogue path all the way through the picker (including label resolution); normal refresh remains separate. A descriptor is display data, not a chat dispatch opt-in. For this release expose actionable controls only on Codex routes. For labels and manual IDs use a read-only local snapshot: even `priceCatalog({cacheOnly:true})` can start a fetch. Fall back to the local ID and link to Models settings for explicit refresh. Using just `providerOptions` for both discovery and selection would leave the UI guessing; adding global `models.stream` arguments would impose Codex semantics on unrelated providers.

2. **Validate before acquiring network transport or refreshing credentials.** Use the already-loaded, trusted connection/model cache snapshot in inference preparation. Delegate Codex option validation to a pure provider-owned preflight (an optional preparation hook if needed); it must run before connection resolution can perform I/O. Do not trust caller-supplied capabilities. Permit only `{speed?: 'standard'|'fast'|'ultrafast', verbosity?: 'default'|'low'|'medium'|'high'}`. Defaults are no-ops even without metadata; other values require support. Reject invalid input as non-retryable `INVALID_INPUT`. Translate only validated values in `codexStream`; merge `text.format` independently of verbosity and omit `text` when empty. Use the same path for one-shot calls. Do not modify native compaction or replay failed calls on a faster tier.

3. **Normalize raw discovery at the provider boundary, not by weakening SDK validation.** Treat `none` as `off`; filter unknown entries and deduplicate recognized levels. Keep `max` distinct from `xhigh`. If usable levels remain but the default is missing or unrecognized, expose no default: automatic calls omit the whole `reasoning` object, including its summary, rather than serializing `auto`. If an explicit list has no usable entries, store a bounded reason for unavailability (e.g. an optional `reasoningUnavailable: true` flag, mutually exclusive with valid reasoning). Honor it before choosing a profile, including after cache reload. An absent list retains the old profile path. Absence alone cannot represent both cases: it would re-enable capabilities that discovery just ruled out. Expand the SDK order, cache filters, public schemas and all selection paths together; do not rewrite other providers' effort profiles or wire aliases.

4. **Persist only explicit chat choices.** Use an owner-authorized session preference store keyed by `(agent_id, connection_id, account_binding, native_model_id)`, with at most one row per tuple and optional speed/verbosity overrides. Default/default needs no row. Read/write through session helpers, not transcript messages, connection settings, display names or a global model preference. Link preferences to the lifetime of their owning session/connection; forks and delegates start without rows. On a route switch, restore only that route's preferences. Check authorization, the current route and cached support on explicit edits; reject stale edits, including those from a picker opened under an earlier account binding even if the selected tier is supported now. Publish each successful current-generation refresh together with invalidation of unsupported overrides across all affected chats, open or closed; retain a one-time reset notice for the owner. At dispatch, reconcile already-saved preferences with the same capability snapshot used to prepare the request: clear just the unsupported value, notify the owner and continue with the default. Applying defaults to saved state is not a license to downgrade explicit SDK calls. A request already sent keeps its options and is never replayed.

5. **Bind discovery, consent and dispatch to the same authenticated account.** `codexListModels` and Responses must build `chatgpt-account-id` from the same trusted auth record as the bearer token; omit the header if the record has no account ID. Keep a server-owned opaque account generation on the connection. Preserve it on process reload and ordinary token renewal for the same verified account; invalidate it on logout, account replacement or loss of verifiable identity. Do not use a token, its expiry or the editable connection name as the binding. The picker needs only an opaque revision to reject stale edits, not the account ID.

   On renewal, establish identity from fresh, trusted account evidence in the new credentials. Neither a retained ID token nor the previous account ID proves continuity. Preserve the generation only on a confirmed match; if fresh evidence identifies another account, start a new generation. If fresh evidence is absent or internally contradictory, clear the binding and omit the account header.

   Tag Codex discovery snapshots with the generation that issued the request. Read and publish a snapshot only while its generation is current, including on failed refresh and late completion. Account invalidation also invalidates that generation's saved speed and verbosity in every chat; a later login cannot revive them. An unknown identity never authorizes overrides, but ordinary authenticated requests can still use defaults. Pin the issuing generation outside the `models.call` retry loop for all options; explicit overrides bind at preflight. Unknown identity permits one otherwise valid default attempt, never a retry. A verified routine renewal need not prevent an otherwise safe retry. Check the prepared generation against the credentials used for each dispatch: if they differ, do not send options prepared for the old account. Reconcile a chat request at defaults before sending; fail an explicit SDK override rather than downgrade or replay it.

6. **Fence auth writes, not just failures.** Reserve a durable login-intent revision before the first device-code request. New login, cancel and logout supersede pending work; compare intent again in the transaction that stores credentials. A fresh generation must never reuse a deleted generation, even if the secret row restarts at version 1. Key shared token refresh by connection, generation and issuing credential revision; return an immutable token/header/revision/generation tuple to each waiter. Condition successful and failed writes on both issuing values and commit identity changes with catalogue, preference and notice invalidation. Never join a stale token to a separately reread account ID.

7. **Order consent changes with dispatch.** Resolve saved choices only at the agent path generating the user-facing response; a caller-supplied SDK `sessionId` is not authority. Keep a server-owned edit revision even when returning to defaults removes the override row. Check ownership, CSRF on browser mutations, expected route, binding and edit revision inside the write. Serialize saves, catalogue publication and final admission on the affected connection/route. Recheck the generation, latest published capabilities and current choice after asynchronous preparation, at the irrevocable transport handoff; use a shared admission gate across workers, not a process-local lock or an unchecked gap before fetch. Do not hold a database transaction while awaiting the remote response. Insert a notice in the same transaction as a reset; give it a stable ID, use a single active owner presentation/claim, release abandoned claims and acknowledge idempotently only after display. Reading the bridge is not acknowledgment. Drafts have no controls or preference rows; the creation request uses defaults.

8. **Keep opaque context within its origin.** Stamp SDK sticky state and Codex checkpoint envelopes with a server-verifiable generation binding (not an editable account name or an unchecked caller-supplied generation). Bind the marker to the opaque content and its existing scopes. Verify before network and against the dispatch credentials, including after reload. Suppress sticky state for unverified identities. On a switch, drop chat sticky state; rebuild a request without a foreign or untagged checkpoint only when complete compatible history is available. Otherwise stop with an actionable recovery message; never silently truncate, send the old encrypted content or modify a transcript to repair it. The native compaction wire body and strategy are unchanged.

9. **Publish authoritative discovery only.** Validate the Codex envelope before normalizing individual optional fields. A missing/non-array list, unusable model identity, interrupted or detectably partial/over-limit result is a failed refresh, not mass removal. If the source declares more pages, finish them consistently or reject the result. Valid empty discovery is authoritative. Failure fallback reads the latest valid generation and published sequence, not the snapshot captured at refresh start. Unknown optional capability names alone do not invalidate an otherwise valid catalogue.

## Risks / Trade-offs

- **Unexpected quota consumption** → no implicit acceleration, no inheritance, and a quota notice at the control. A removed tier is never mapped to another fast tier.
- **Stale or offline catalogue** → use the last successful catalogue for the same route and current account binding only. With no metadata, disable overrides, not ordinary requests. The normal refresh path replaces capabilities; opening the picker or rejecting an option must not refresh them.
- **Widening an exported union** → update public contract fixtures and exhaustive validators together. Verify `xhigh` → native `max` stays unchanged where already used. Downstream exhaustive switches may need a new case even though all old requests remain valid.
- **Late authentication rejection** → for token refresh rejection and any backend HTTP 401 that can mark `needsLogin`, pass the credential revision and account generation from the original request to the conditional write. If either has changed, fail that request without mutating current auth, catalogue, preferences or notices.
- **Overlapping catalogue refreshes** → allocate an ordered request number per connection and generation before discovery. In the same transaction as publication and preference reconciliation, reject a result older than the latest published request. Return the current snapshot, not the discarded result, including on failure fallback.
- **Refresh races or edited stale tabs** → validate against the current snapshot server-side. Reset only persisted choices; never retry an already dispatched request in response to a reset.

## Migration Plan

Add the account binding, optional cache fields and preference store first, with no backfill and no default rows. An untagged legacy catalogue never authorizes a speed or verbosity override; keep ordinary legacy model listing and default inference compatible. Deploy SDK validation, provider parsing and dispatch before exposing the picker. Ordinary listing and checkpoint-free sessions need no refresh; never retroactively attest the origin of a legacy checkpoint. For a chat that cannot rebuild complete history, explain that the owner must restore compatible history or start a new chat. With a current verified account, the next successful normal catalogue refresh enables newly discovered controls. On rollback hide controls and stop reading/writing their preferences; the additive store can remain dormant. Before starting old readers, quiesce new writers and drain in-flight calls; use an offline, idempotent compatibility step on isolated/supported storage. Clear incompatible Codex catalogue snapshots (including lists containing `max`), reset only explicit persisted `max` to `auto`, and prevent older readers from replaying generation-bound or untrusted checkpoints. Do not downgrade a chat that depends on such a checkpoint unless complete compatible history can be restored safely; report blocked chats instead of discarding context. No previous-adapter refresh or network is required for cleanup. Preserve unrelated routes and preferences; rehearse the old binary's default request with mock transport, never live traffic.
