# Design

## Context

`fetchAvailableModels` describes three different things: `models[id]` contains native entries and their measurements; `agentModelSorts[].groups[].modelIds` and `tieredModelIds` list selectable IDs; `groupedModels[groupId].supportedThinkingLevels` describes picker choices. The current adapter keeps individual Gemini IDs and assigns levels from a Gemini 3 name pattern. Its stream adapter sends the selected ID and can independently set `thinkingLevel`. Its provider declaration has no `usage` adapter, so a connection test supplies status but no quota windows.

On the consuming side, the model cache explicitly allowlists descriptor fields, the quota endpoint creates one account per connection, and the sidebar uses four grid slots per row with a shared rail indicator in compact mode. Merely returning extra windows would produce a `+N` badge, not the requested cards. The examples below are synthetic or public model IDs, not an account dump.

## Goals / Non-Goals

**Goals:** Keep picker identity, native dispatch and quota measurement distinct. Make either family readable at a glance while preserving the identity, accessibility and click destination of the underlying account.

**Non-goals:** No OAuth, pricing or retry-policy changes; no other account, endpoint or Gemini CLI fallback. No generic alias language, GPT-OSS support, new quota polling loop or account-wide quota period inferred from a reset timestamp. Do not store raw discovery payloads, experiments, prompts or credentials.

## Decisions

### 1. Join the three inventory views before projecting the catalogue

Build an ordered, deduplicated list from the advertised visibility lists (sorted lists first, then tier-only entries in provider order). Intersect with actual, non-disabled entries. Use the structured `modelProvider` attribution for Gemini and Claude (`MODEL_PROVIDER_GOOGLE` and `MODEL_PROVIDER_ANTHROPIC`); do not rebrand an unknown vendor from display text. Join each supported `thinkingSuffix` to the corresponding **existing visible** native ID: for example group `gemini-4-neon` and suffix `xhigh` match `models["gemini-4-neon-xhigh"]`. String concatenation is for lookup, never permission to send a guessed ID. Check family and thinking eligibility; accept only unambiguous recognized SDK levels. An ambiguous membership or collision between a group key and a separate native ID must not hijack the native route: retain distinct eligible native entries without inferred controls for the ambiguous case. Do not equate `-tiered` entries, determine membership from equal labels, or use numeric `thinkingLevel` as a list of options.

Expose the provider-issued group key and display name as the stable catalogue choice; it is not the ID for generation. Native members appear in the group's mapping, not again as picker rows. Entries outside a verified group stay native choices with their own limits. Publish a group limit only from its members: if all report the limit, use the lowest sound bound; otherwise leave that limit unspecified. Do not invent prices. A single native entry is not evidence for multiple user-adjustable levels. This avoids hard-coding the behavior of this account or a model generation into the UI.

### 2. Cache member identity separately from wire settings

Use a bounded, optional group descriptor in `ModelInfo`: provider group key, recognized `effort → nativeId` entries in provider listing order and an optional verified default member. Publish `reasoning.supported` from that map. Validate and preserve the descriptor in `models/catalog/listModels` and its persistent cache; `reasoning.wire` stays a map of **parameter values**, not a place for native IDs. A normal refresh updates the group atomically. Scope it to the signed-in connection; discard old-account state on logout, revoked grant or replacement, including late results from the old binding.

New selections use the advertised group key in the existing `provider/account:model` route format. Chat, delegation, settings and availability checks derive choices from the same cache. Level selection lives in the SDK, not the adapter: `models.stream` sees `reasoning.variants` on the cached model, removes owner-disabled members, normalizes the preference against the remaining levels with the existing nearest-level rule (`auto` → declared default member if eligible, else first eligible in provider order; `off` without an `off` member → lowest level), and hands the provider `req.model = <member native ID>` with no effort value. The resolution keeps requested/applied for diagnostics. Delegation and other explicit entry points validate against the same variant levels and reject an unsupported explicit level, as they already do. No eligible member, or a route absent from the cached catalogue, fails `MODEL_UNAVAILABLE` (`invalid_input`, acceptance `none`) before any request. Existing chats are not migrated: a route that is not a current choice simply fails. A failed network refresh is not evidence of removal. Pin the resolved native ID for a request and its retries. Do not rewrite chats, defaults, history or owner disable lists during refresh.

### 3. Verify generation independently from discovery

Keep the existing Antigravity connection transport, project and outer request envelope for both families. In the grouped path send the resolved native ID, not the group key or an independent, potentially contradictory Gemini `thinkingLevel`. Do not forward a generic Gemini thinking setting to Claude. Exercise the family-specific inner request and wrapped stream with sanitized protocol fixtures: request model, streamed text, terminal usage, tool-call ID/result and required opaque continuation/signatures across turns. Keep Gemini's per-call signatures and established error/retry behavior. A model-list result, a plain-text Claude response alone, or a request to a separate Anthropic connection cannot establish tool compatibility.

### 4. Project quota from native observations, not picker rows

Read `models[id].quotaInfo` for provider-visible members before collapsing choices; locally hiding a model does not change the service's measurement. Keep native ID, safe display label, `family: gemini | claude`, observation time, optional remaining fraction and reset. Accept a finite fraction in `[0,1]` and a valid reset timestamp independently. Expose `usedPercent = 100 × (1 − remainingFraction)` and `resetAt` in epoch milliseconds. Do not put a percentage into the unitless `remaining` amount. Missing, nonnumeric or out-of-range values are unknown; zero is valid. Use `scope: model`, a stable native observation identity and no standard period. Do not conflate two families even when observations coincide.

Add optional typed family metadata to the usage-window normalization and quota API projection (`additionalWindows`); never derive the family from a label in the frontend. Retain one account ID. Cache the **allowlisted observations** per signed-in connection using the existing usage refresh cadence, independent of the long-lived model catalogue. Refresh through the existing authenticated discovery operation, never through generation. Settings, endpoint and sidebar details consume that same dated snapshot; re-render, hover or opening details must not force a fetch. Preserve normal unavailable/stale states, invalidate observations with the account, and suppress requests while disabled or signed out. If safety caps truncate observations, carry incomplete coverage for the affected family; do not present a partial set as a complete allowance.

### 5. Two card slots; one account

For an Antigravity connection project one card per shown family in the existing grid, Gemini first, Claude second. A family is shown only while the cached catalogue has at least one of its models not disabled by the owner; with no shown family the connection keeps its ordinary status card. Reserve consecutive slots on the same row (move the pair to the next row when only one slot remains). Keep other cards in their existing order and keep their period-based **used** legend; scope that legend to period cards. Each family card visibly identifies Antigravity, the family and **remaining**, not a naked percentage. Its accessible name includes the account, and its details target the same account with that family selected. Show the same pair on opening the mobile usage section. The narrow rail keeps one accessible trigger with both readings in its details. Pointer, focus, keyboard activation and touch must all work; keyboard dismissal returns focus without changing accounts.

Within a family, compare unrounded measurements first and round only for locale-aware display. Equal known fractions give one figure; differing fractions give a min–max range, never a mean. Group detail rows only when both fraction and reset are known and match, retaining all contributing model names. Different resets remain separate even if the card shows one percentage. Mark a partly known family as partial; if nothing is measured, show `no data`, not 0% or 100%. Display reset times in the user's local timezone, observation time for stale data, and use the worst measured **used** severity for that family. Color is not the only cue. Settings uses the same grouping and units from the same snapshot. Do not create two API accounts (which would double-count the connection), substitute `+2` for numbers, or assign a model-specific limit to the five-hour/week/month columns.

## Risks / Trade-offs

- **Inventory changes between listing and dispatch** → recheck the current local binding, mapping and disables; a saved level follows the SDK nearest-level rule among eligible members, an explicit unsupported level is rejected, and a route with no eligible member fails `MODEL_UNAVAILABLE`.
- **Old chats break** → accepted: saved routes are not migrated; a route that is no longer a current choice fails `MODEL_UNAVAILABLE` and the owner reselects. A legacy cache advertises no invented groups and upgrades on the next normal refresh; opening a picker does not fetch.
- **A group or family looks like a billing pool** → preserve per-ID evidence and reset times; the cards summarize observations, not entitlement or future reset behavior.
- **A compact grid obscures units or account identity** → test the pair next to a used-percentage provider, at a row boundary, with two accounts, long labels, keyboard focus and touch. Unknown and partial must have text, not just a color.

## Migration Plan

No table or transcript backfill. Deploy additive cache/API readers before relying on the new fields; old routes are not migrated and fail `MODEL_UNAVAILABLE` once they are no longer current choices. Invalidate incompatible per-connection projections on sign-in changes, not globally. If the change is rolled back, restore the old catalogue by normal refresh: a group-only route that an older build cannot resolve must be shown as unavailable for manual reselection, not sent upstream as an invented native model. Exercise both snapshot shapes with isolated fixtures; no live credentials or generation are required for this change.
