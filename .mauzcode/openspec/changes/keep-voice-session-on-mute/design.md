# Design: Connected mute and selective dictation deletion

## Context

`VoicePanel` maps Space and the on-screen toggle to `useVoicePanel`. Today its `pause()` calls `end('paused')` in `useVoiceCapture`: drain the worklet, release audio, send `finish`, wait for `completed`, close the socket. The next toggle starts another capture generation and draft dictation segment. `LiveComposer` also calls `pause()` to finalize before sending; changing what that method means without splitting these callers would allow a partial submission.

The relay at `/voice/session` already accepts sequenced 20–100 ms mono PCM16 frames. Only valid incoming audio renews its 30-second idle timer. The server enforces a separate five-minute deadline from readiness, checks edit access, and ends superseded sessions. The SDK's voice activity detector already handles digital silence and pending speech. See `proposal.md` for motivation. [Codex's capture worker](https://github.com/openai/codex/blob/1476a08f1b410e359e64becf2494bc248743e396/codex-rs/voice-host/src/capture_worker.rs#L111-L121) is a behavioral reference for sending generated silence on mute, not a reason to adopt WebRTC, Opus or its key bindings.

The current Clear button calls `DraftDictation.clear()` across this draft's inline and panel sessions, including closed ones. Ownership is tracked per phrase: an overlapping manual edit detaches the entire phrase. Clear ignores detached spans and removes unedited ones without closing capture. The panel transcript is read-only; there is no editable caret to use for word deletion.

## Goals / Non-Goals

- Keep a healthy connected run usable immediately across mute/unmute, without exposing microphone samples from a muted interval. Continue receiving recognition of earlier speech.
- Do not extend the maximum session duration, auto-reconnect, change inline dictation, or introduce provider-specific controls. Do not require a new permission, setting or transport.

## Decisions

1. **Separate input state from session lifetime.** A ready run has two reversible states, `listening` and connected `muted`. Both own the same capture generation, socket, provider stream, route, countdown and draft dictation segment. Mute/unmute only operates on that run; neither action sends `start`, `finish` or `cancel`, or awaits recognition. Keep setup cancellation and terminal cleanup separate. With no live run (after send, failure or expiry), offer an explicit start/retry, not unmute. Keeping today's `paused` state for both meanings would make send and retry ambiguous.
2. **Send generated silence over the existing PCM stream.** Disable the microphone track on mute (`enabled = false`); keep the track and audio graph allocated. In muted mode the worklet uses the audio render clock to produce zeros even when there is no input channel. Use the negotiated sample rate, normal frame cadence/size and the same monotonically increasing wire sequence. Do not read microphone samples to construct silence. This keeps the relay alive and lets normal segmentation settle pre-mute speech without a special commit or a silence-only phrase. Stopping all frames triggers the idle timeout; adding protocol controls or disabling the server watchdog would change the SDK unnecessarily.
3. **Make the audio boundary explicit.** Disable live input immediately and serialize worklet transitions. Separate samples known to precede mute from muted samples at the cutover: drain only the pre-mute tail, pad with zeros if necessary, and clear partial framer/resampler history before admitting fresh input. Use a local toggle epoch or equivalent ordered boundary to reject stale worklet callbacks after quick toggles; do not reset the wire sequence or session generation. If a queued sample's origin cannot be established, prefer silence to disclosure. On unmute enable live input only for the current transition. This is stronger than changing a React flag or relying on `track.enabled` alone.
4. **Keep transcript and submit semantics independent of mute.** Route pre-mute revisions to the same `DraftDictation` segment even while muted, retaining manual-edit and selective-clear protection. Enter from either live state drains the run via the terminal finish path, receives outstanding finals, then submits once through the existing lock/queue; a failure leaves the draft unsent. After acknowledgement the panel remains open but disconnected with the mic off. Escape cancels and returns to editing; teardown, device/transport failure, supersession and access loss still retire the whole run. Inline stop still finishes and releases the session.
5. **Expose the distinction on keyboard and touch.** Keep the existing panel-scoped Space and button, desktop tooltips, focus rules and mobile layout. Use localized action names for mute/unmute and a distinct start/retry action when disconnected. While muted, stop the waveform, announce the microphone state (not transcript text) and show the live countdown against its original deadline.

6. **Delete from owned spans, not from the end of the draft string.** Put `deleteLastWord` beside the existing bulk operation in `DraftDictation`. Use the rightmost eligible span in current draft offsets across sessions, not the last callback to arrive. Find the last complete word within that span using Unicode word boundaries for the transcript language (e.g. `Intl.Segmenter`); include trailing punctuation owned by the span and remove only redundant dictated spacing. Treat any remaining punctuation-only fragment as one removable unit. Never consume a neighboring typed space, newline or punctuation. Replay exact span edits into other sessions using the existing ledger mechanism, so repeated words are not mistaken for one another. A word deletion freezes further recognition rewrites of that phrase without detaching its surviving prefix from future word/full deletion; newly reported phrase IDs remain live. Ordinary manual edits retain today's whole-phrase protection. A regex over the whole string, or treating the deletion as ordinary typing, would violate one of those guarantees.
7. **One button, one action per gesture.** Map unmodified Backspace and exact Ctrl+Backspace to word and full deletion, only on the voice frame/read-only content. Consume a handled deletion key (including repeat) to avoid browser navigation; ignore repeat, composition and unrelated modifiers. Leave editable fields and native button keys alone. A regular click (including an assistive-technology click) deletes one word. For the primary pointer only, arm a **600 ms** hold timer on press; on expiry clear once, disarm and consume that gesture's follow-up click. Do not mutate the draft on pointer-down. Cancel a pending gesture on drag/exit, pointer cancellation, focus loss, unmount or loss of permission to edit; recheck the current draft identity, editability and send lock at execution. A canceled gesture never becomes a short click in the draft. Expose the primary action in the accessible name and both actions/shortcuts in the description and desktop tooltip; touch help describes tap/hold. Keep the current desktop-disabled/mobile-hidden behavior when there is nothing to clear.

## Risks / Trade-offs

- **Audio buffered across a toggle** → Test non-zero markers immediately before, during and after mute, including a partial frame, queued callbacks and rapid toggles. The muted marker must never reach the wire, including after unmute.
- **A muted connection still uses time and bandwidth** → Show the continuing countdown. Keep normal backpressure, idle and hard timeouts; a suspended browser that cannot send frames, a lost socket or a provider failure is still an error, not a reason to reconnect silently.
- **Late words or a duplicate send** → Keep one phrase ledger through mute and exercise delayed finals, manual corrections, repeated Enter and finish failure with a fake recognizer. Never close the ledger merely because the mic is off.

- **A wrong word, or more than one action, gets removed** → Cover mixed typed/dictated text, punctuation in Russian, manual corrections, repeated words and late finals in ledger tests. Use a fake clock on mouse and touch pointer events around 600 ms; include a phrase arriving between hold and release, a canceled gesture, native button activation and focus in a text field.

## Migration Plan

This is a client-side behavior change. Ship the controller, panel and documentation together; there is no wire negotiation, schema migration or provider configuration change. Old clients retain finish/restart behavior against the same relay. Reverting the client restores it.
