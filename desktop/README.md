# MauzCode Desktop — подключение к существующему серверу

Electron-клиент открывает ваш сервер MauzCode; Bun, Postgres, агент и инструменты разработчика на компьютере пользователя не нужны. Доступ к сети/VPN должен уже работать. Сборка **пилотная**, публичного релиза и подтверждённых платформ пока нет: [статус проверки](PILOT.md).

## Первый запуск и смена сервера

1. Введите адрес, например `https://mauzcode.example.com`, `http://192.168.1.20:3000` в LAN/VPN или `http://localhost:3000` на этом компьютере. Для HTTP вне loopback требуется явное согласие: трафик и вход не шифруются. Предпочитайте HTTPS. Не вставляйте логины, пароли, параметры или фрагменты в адрес.
2. Нажмите **Проверить и подключиться**. Клиент проверяет `/auth/session` из профиля нового сервера, загружает страницу и повторно проверяет сессию. Если нужен вход, завершите его в открывшемся окне сервера. Пока не загружен интерфейс и не подтверждён вход или открытый доступ, прежний чат остаётся открыт, `server.json` не изменяется. Проверку можно отменить. При недействительном сертификате нужно исправить сертификат, а не отключить проверку.
3. **Ограничение пилота:** если OIDC/Google требует перейти на другой origin, новый вход таким способом невозможен. Клиент объяснит причину и вернёт в настройки, сохранив прежний чат и профиль. Вход в системном браузере не авторизует встроенный Chromium. Уже действующая сессия на том же сервере продолжает работать.

Открыть настройки позже: **Сервер → Настройки…** (`Ctrl+,` / `Cmd+,`). **Повторить подключение** (`Ctrl/Cmd+R`) в работающем чате восстанавливает живую подписку без перезагрузки страницы или повтора отправки. Если старый сервер не сообщает статус транспорта, клиент проверит сессию, не трогая черновик. После ошибки начальной загрузки или падения renderer можно заново открыть сохранённый сервер. **Вид → Назад** и **Обновить страницу** действуют на сам документ: используйте полную перезагрузку только намеренно. Все кнопки, темы, фокус и сочетания клавиш описаны в [настройках](SETTINGS.md).

## Сессии и доступ к компьютеру

- Сохранённый адрес — прежний `server.json` в `app.getPath('userData')`. Cookies и хранилище сайта остаются в прежнем Chromium-профиле отдельно для каждого origin (схема, имя и порт). Клиент не копирует пароль, не превращает временные cookies в постоянные и не очищает профиль при смене сервера. Срок входа определяет сервер. Для перехода со старой версии первый пилот устанавливают вручную **поверх** неё, не удаляя данные.
- Серверное окно изолировано (`sandbox`, `contextIsolation`, `webSecurity`); без Node, файловых API и IPC настроек. Локальный preload настроек доступен только упакованному документу. Камера и разрешения сторонних фреймов запрещены.
- По явному запросу доступен системный диалог **Сохранить как**, без автоматического открытия. Для существующей диктовки нужен HTTPS или loopback, согласие для текущего origin и системное разрешение. В настройках можно отозвать доступ. Отказ не мешает печатать. [Подробности и ограничения](NATIVE.md).
- Системные уведомления включаются в настройках. На поддерживаемом сервере они показываются для авторизованного пользователя при завершении работы агента или ожидании ответа, когда окно свёрнуто/скрыто. Нажатие открывает соответствующий чат после повторной проверки доступа. Выход из аккаунта, смена сервера и явный выход из программы прекращают действие старых уведомлений. Без подписки, подходящей сессии или системной поддержки обычный чат остаётся доступным.

## Трей и завершение

Закрытие основного окна с рабочим треем скрывает его, **Показать окно**, щелчок по иконке или повторный запуск возвращает тот же экземпляр; на macOS доступен Dock. **Выйти** и `Cmd+Q` завершают клиент. Если иконка не создалась или в Linux не удаётся подтвердить доступный системный индикатор, закрытие последнего окна завершает приложение, а не оставляет его скрытым. Для обнаружения индикатора Linux используется `dbus-send`; без него безопасный вариант — обычное закрытие. После явного выхода уведомлений нет.

## Сборка и обновление

Обновление не зависит от адреса сервера. Пилотный пакет с утверждёнными публичными настройками читает отдельный репозиторий без авторизации, проверяет подпись манифеста, совместимость, файл и применимую подпись ОС. В настройках доступны проверка, скачивание и **Перезапустить и обновить**. **Позже** не устанавливает отложенное обновление даже при обычном выходе. Без настроек дистрибуции обновления недоступны, чат работает. Порядок сборки и проверки подписанных NSIS x64, DMG/ZIP Intel и Apple Silicon и AppImage x64 — в [руководстве по выпуску](RELEASE.md), а не в меню выбора сервера. Публикация и стабильный канал требуют отдельных решений.

### Как запустить клиент сейчас

Готового установщика для скачивания пока нет. На компьютере с графическим интерфейсом нужны копия этой версии репозитория, Bun и Node.js 22.12 или новее (предпочтительно LTS). Из корня репозитория выполните:

```sh
cd desktop
bun install --frozen-lockfile
bun run dev
```

При первом запуске Electron скачает бинарник для вашей ОС, если его ещё нет, поэтому потребуется доступ к сети. В окне клиента введите адрес уже работающего сервера MauzCode и нажмите **Проверить и подключиться**. `localhost` подходит, только если сервер на том же компьютере. Это запуск из исходников, без установки серверной части и без автообновлений. На Linux запускайте от обычного пользователя, в графической сессии с работающей песочницей.

Для разработки: `bun run test` проверяет локальные сценарии (нужны также тестовые зависимости корня репозитория), а `bun run check` собирает JS без запуска Electron. Иконки в `desktop/assets/` генерируются командой `bun run icons` из общего `src/ui/assets/icon.svg`. На Windows `bun run prefetch:win` может заранее загрузить закреплённый архив в кэш с проверкой SHA256.
