# Codex catalogue and wire evidence

`0.170.0.json` records sanitized evidence from [openai/codex `rust-v0.170.0`](https://github.com/openai/codex/tree/29eb79e9866b3262a777fdf8195c1b9e63684c91), not a list of enabled models. Never infer an account's capabilities from this fixture.

- **Catalogue:** `codex debug models --bundled` on the official Linux x86-64 standalone release, keeping only the shown fields of one entry. Compare the tagged [models.json](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/models-manager/models.json) and [`supports_fast_mode`](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/protocol/src/openai_models.rs#L1124-L1131): both `fast` in `additional_speed_tiers` and `priority` in `service_tiers` designate Fast.
- **Ultrafast:** the [upstream mock-server test](https://github.com/openai/codex/blob/29eb79e9866b3262a777fdf8195c1b9e63684c91/codex-rs/core/tests/suite/client.rs#L119-L167) supplies a one-tier descriptor for `ultrafast` or `priority` and asserts `service_tier` in the actual request. The Ultrafast descriptor here reproduces that override; it is **not** a claim that the bundled model or a real subscription offers Ultrafast.
- **Wire capture:** ran the unmodified CLI (binary SHA-256 `880819aab735adcf16f36cd628940b9f1e652a36c01d10a5d32f83cc84902971`) three times with empty isolated home, no credentials, `--ephemeral`, a loopback Responses provider and a terminal SSE fixture. `model_catalog_json` contained the original bundled descriptor for the first two runs, and that descriptor with only the upstream Ultrafast override for the third. With no `service_tier`, `service_tier="priority"`, and `service_tier="ultrafast"`, respectively, the server captured the three request projections in the JSON file. No live provider/account was used. Headers, prompts and unrelated protocol fields are intentionally excluded.
